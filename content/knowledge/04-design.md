# 设计的设计与管理

## 1. 回顾

在 [00-opframework.md](./00-opframework.md) 中，设计被定义为：

> 让产物被人理解。最终用户或相关方——任何一个需要消费这个产物的人——能够看懂、找到他们关心的信息、做出下一步判断。回答"人看到的是什么"。

设计只负责可理解性。不对正确性负责（那是策略的责任），不对数据真实性负责（那是事实的责任）。衡量标准只有一条：目标读者是否能用最少的心智成本获取他们需要的信息。

在四类资产的关系中，设计不参与框架—策略—事实的互动循环——它是正交的呈现层。任何需要被人消费的资产，都可能需要设计包裹它。

本文讨论设计的管辖边界、治理的两层模型，以及设计与叙事框架的协作。

## 2. 设计管什么、不管什么

设计的管辖范围窄于直觉。把一件事归入"设计"和归入"框架"或"策略"，后果完全不同——前者放权，后者控权。

### 2.1 设计管的事

- 信息的视觉呈现：字体、字号、颜色、间距、布局
- 信息的组织顺序：先展示什么、后展示什么，什么放在首屏、什么放在折叠区
- 信息的格式选择：用表格还是图表、用绝对数值还是百分比、用折线图还是柱状图
- 文案的语气和措辞："下降 15%"还是"回落至正常区间"
- 交互路径：读者如何从一个信息节点导航到另一个

### 2.2 设计不管的事

- 展示哪些信息（这是叙事框架的责任）
- 什么算正确（这是策略的责任）
- 数据的真实性和来源（这是事实的责任）
- 信息之间的逻辑依赖（这是数据框架的责任）

一条好的设计决策和一个越界的设计决策之间的区别：设计决定"这个指标用饼图还是柱状图"是管辖范围内的事；设计决定"这个指标不该展示给这个受众"是叙事框架的决策，不是设计的决策。

## 3. 设计的两层治理

设计的变化速度最快、碎片化程度最高——和行业惯例、公司架构、专业设计人才规模都有关系。试图在每一处设计决策上强加中央控制会失败。

正确的模型是两层的：

```text
原则层（集中，变化慢）
  ├── 品牌资产：logo, 色板, 字体
  ├── 设计原则：信息层级, 可访问性, 移动端优先
  └── 反模式清单：不能做的事

实现层（共享，变化中等）
  ├── 模板：周报模板, PPT 模板, 看板模板
  ├── 组件：按钮, 表格, 卡片, 图表
  └── Design Token：颜色变量, 间距变量, 字号阶梯

自由层（放权，变化快）
  └── 每个人在模板和 token 基础上自由调整
```

### 3.1 原则层

原则层回答"我们是一个什么样的组织"——在视觉和沟通层面。品牌资产定义了可识别的视觉边界（颜色不能比这个更鲜艳、字体不能比这个更花哨）。设计原则定义了信息组织的底层逻辑（最重要的信息永远先出现、所有图表必须有标题和单位）。

原则层变化最慢——品牌换标是年度甚至多年的事件。适合集中管理，强制所有人遵守。

### 3.2 实现层

实现层提供"默认即可用"的资产。模板让非设计背景的人不需要从空白页开始——填入内容就能产出基本合格的产物。Design token 让颜色、间距、字号的选择不再需要每次手动调——引用 token 变量，全局修改时自动更新。

实现层的目标是降低设计决策的次数。不是让每一份产出都经过专业设计评审，而是让默认路径产出的东西就已经足够好——只有需要偏离默认时才需要判断。

### 3.3 自由层

在模板和 token 覆盖不到的范围内，每个人自由裁量。一段临时邮件不需要套模板、一个快速的数据查询不需要配色方案。

自由层的存在不是因为设计不重要，而是因为中央控制的成本高于收益。试图统一所有设计产出的组织会陷入两种失败模式中的至少一种：要么审批瓶颈导致产出速度归零，要么规范被系统性地无视而成为僵尸文档。

## 4. 设计与叙事框架的协作

设计与叙事框架的边界是框架中最容易混淆的一对（回顾 [01-framework.md](./01-framework.md) 2.1 节）：

- **叙事框架**决定"哪些信息以什么结构出现"——周报有五个板块，第三个板块放重点项目进展
- **设计**决定"这些信息以什么形态被人感知"——重点项目进展用表格还是列表、已完成的项目用绿色还是灰色

二者协作的典型模式：

1. 叙事框架定义信息架构（section 层级、每节的信息类型）
2. 设计为每种信息类型提供默认的呈现方式（表格样式、图表类型、强调方式）
3. 在自由层，作者可以覆盖设计的默认选择，但不能改变叙事框架定义的信息架构

叙事框架的变更比设计原则的更慎重——改变周报的板块结构会影响所有读者对"什么是本周重要的事"的认知。设计原则的变更比模板的更慎重——改变色板或字体层级会影响所有产物的视觉一致性。模板和组件的变更相对轻量——它们是共享资产，改善即可发布。

## 5. 设计已摸到的边界

### 5.1 艺术

当一个设计决策的理由是"这样更好看"或"这样更有感觉"时，它已经进入了艺术的领域。这不是贬低——好的设计确实有美学维度——但它不可工程化。不能把"这样更好看"写成一条 validator 或 assertion。

框架对这件事的态度不是否认审美，而是**将美学限制在自由层**。原则层和实现层不追求"好看"——它们追求"清晰、一致、无障碍"。好看是加分项，在满足了清晰和一致之后，由执行者自由发挥。

### 5.2 品牌

当设计跨越到品牌时，它不再只是"让人理解"，而是"让人产生特定情感和联想"。品牌是设计中最难以量化和规则化的维度。

框架的态度：品牌的核心资产（logo、色板、关键视觉语言）进入原则层集中管理。品牌的应用规范（广告、社交媒体、活动物料）由专业设计师单独处理，不纳入运营框架的模板体系——这些不是"运营工作"，不适合 pipeline 化。

## 6. 设计与另外三类资产的关系

- **框架 → 设计**：叙事框架向设计提供"展示什么信息"的清单。数据框架向设计提供字段名、类型和关系——设计使用这些来构建表单、表格和详情页的布局。
- **策略 → 设计**：策略的判定结果（通过/不通过/告警/风险等级）需要被设计呈现。设计不决定策略的规则，但决定策略状态如何被读者感知——一个告警用红色圆点还是黄色横幅，影响读者的行动紧迫感。
- **事实 → 设计**：事实是设计呈现的原材料。设计不改变事实，但选择如何呈现事实——同样的 DAU 数据，放在首屏大数字区域还是放在第三页的附表中，决定了它是否被读者看见和记住。
