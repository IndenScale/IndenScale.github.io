# AgentHooks 与 Agent Midware 概念定义

## AgentHooks（钩子接口层）

**定义**：AgentHooks 是一种标准化的**事件驱动接口协议**，定义了 Agent 运行时在特定时间点与外部代码交互的契约。

**核心特征**：

- **标准化协议**：统一的事件命名、输入输出格式（JSON）、阻断/放行决策机制
- **时机定义（When）**：明确的事件触发点（PreToolUse, PostToolUse, SessionStart, SessionEnd 等）
- **通信契约（How）**：stdin/stdout 数据格式、退出码语义（0=放行, 2=阻断）、超时控制
- **无业务逻辑**：本身不实现任何具体功能，只提供"挂载点"

**类比**：

- 就像 USB 接口标准——定义了针脚、电压、通信协议
- 就像操作系统的系统调用表——定义了用户态与内核态的边界

---

## Agent Midware（中间件逻辑层）

**定义**：Agent Midware 是**挂载在 AgentHooks 上的具体处理逻辑**，负责在特定事件触发时执行实际的业务功能。

**核心特征**：

- **业务实现（What）**：包含具体的处理代码、规则引擎、决策逻辑
- **可组合性**：多个 Midware 可以在同一个 Hook 点上链式执行
- **领域特定**：安全审计、代码格式化、性能监控、合规检查等
- **可插拔**：遵循 AgentHooks 协议的任何 Midware 都可以热插拔

**类比**：

- 就像插在 USB 上的设备——可以是鼠标、键盘、U盘、摄像头
- 就像系统调用之上的库函数——实现具体的文件操作、网络通信

---

## 关键区分

| 维度       | AgentHooks          | Agent Midware          |
| ---------- | ------------------- | ---------------------- |
| **本质**   | 接口标准            | 功能实现               |
| **关注点** | When & How          | What                   |
| **稳定性** | 长期稳定            | 快速迭代               |
| **生态位** | 基础设施            | 应用生态               |
| **举例**   | PreToolUse 事件定义 | 危险命令拦截的具体规则 |
| **维护者** | 平台/标准组织       | 社区/企业开发者        |

## 为什么需要区分

1. **标准化与创新的分离**：Hooks 标准一旦确立可以长期稳定，Midware 可以百花齐放
2. **跨平台移植**：遵循同一 Hooks 标准的 Midware 可以在不同 Agent 平台间迁移
3. **治理分层**：平台负责 Hooks 的稳定性，社区负责 Midware 的多样性
4. **责任边界**：平台不侵入业务逻辑，开发者不依赖特定平台实现
