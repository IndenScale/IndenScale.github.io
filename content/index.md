## 这是什么

这个站点记录了一套统一框架的构建过程。它的核心命题是：

> **领域知识应该从人脑和模型权重中提取出来，形式化为可执行、可版本化、可演化的资产，部署为 Agent 的工作环境，并在模型失败与人类架构判断的张力中持续生长。**

这套框架目前分布在五个概念层上。下层不依赖上层，上层依赖下层。


## 五层概述

### 知识层（第 2 层）—— 起点

知识层回答一个前置问题：**领域知识长什么样？**

一篇周报、一份审批单、一套合规规则——这些看起来互不相关的工作产物，共享同一套底层结构：它们都可以被拆解为三层（产物/内容/数据），都可以归入四类资产（框架/策略/事实/设计），都遵循同样的变化速率和治理规则。

知识层是整个框架的"类型系统"。它定义了什么是框架（定义维度和自由度）、什么是策略（定义验收条件）、什么是事实（记录发生了什么）、什么是设计（让人理解）。这些定义不是哲学分类——它们是工程接口：框架进入 Pydantic schema，策略进入 pytest 断言，事实进入数据库或 YAML，设计进入模板和 Design Token。

**入口**：[knowledge/](knowledge/)

### 运行时层（第 3 层）—— 消费端

知识资产定义好之后，谁来消费它们？运行时层回答：**Agent 如何被知识约束。**

Agent 不等于 LLM。Agent = LLM + 一套控制其行为边界的脚手架。运行时层定义了三个嵌套的控制回路——会话循环（任务生命周期）、交互循环（人机控制权移交）、行动循环（工具调用与环境交互）——以及两个支撑机制：Hooks（在生命周期事件中挂载判定逻辑）和 Flag（跨进程的文件系统级状态协议）。

核心洞见：你不需要控制大脑（模型权重），你只需要控制大脑与世界的接口。Hooks 是唯一确定性的硬约束——AGENTS.md 和 system prompt 只是建议，模型可以选择忽略；Hooks 在模型行动之前或之后执行，可以阻断、注入、回滚。

**入口**：[architecture/](architecture/)

### 部署层（第 4 层）—— 打包

知识资产定义好了，Agent 运行时准备好了，怎么把它们组装在一起？部署层回答：**什么是 IWE（集成工作环境）。**

IWE 是一个被注入了领域知识的 Agent 沙盒。空白沙盒只回答"Agent 不能碰什么"，IWE 回答"Agent 应该知道什么"——它把知识层的框架（Pydantic 模型）、策略（Validator + Assertion + 结构化评估 + HITL）、事实（材料）和设计（模板）预置进沙盒，Agent 进去就能开始做正确的事，不需要从零理解领域。

IWE 同时是一个天然的训练数据工厂：Agent 在 IWE 里的每一次被 validator 拦截、被 assertion 发现错误，都自动产生一个 `(rejected_output, chosen_output)` 偏好对——这是演化层的燃料。

**入口**：[synthesis/iwe.md](synthesis/iwe/)

### 演化层（第 5 层）—— 生长

知识资产不是一次建完的。演化层回答：**验证器套件如何与模型共同进化。**

Jargon RL 的核心机制是一个两阶段交替循环。范式更新阶段：人类架构师（或半自动失败日志挖掘）扩展框架和策略，覆盖新发现的失败模式。模型学习阶段：模型针对当前验证器套件做纯 RLVR 训练，所有奖励都是确定性的（所有验证器通过 = 1，否则 = 0）。

关键区分：框架修改（路径 A，改变本体层级的结构决策）与策略修改（路径 B，在现有框架内追加验证器），前者不可从失败日志推导，依赖架构师的判断；后者可半自动化。健康的演化要求框架保持对策略的领先——不是堆积规则，而是规则的规则在生长。

**入口**：[synthesis/jargon-rl.md](synthesis/jargon-rl/)

### 工具层（第 1 层）—— 工程实现

让上述各层可操作的工程工具。AtomDoc 实现了知识层"内容与样式分离"的核心公式——对 docx 做 passthrough 保真往返，Agent 在 YAML 层编辑文档内容，OOXML 样式层原样保留。Typedown 为 Markdown 添加了编译期类型检查——让 Agent 产出的结构化文档在人工审查之前就被机器验证。

**入口**：[tools/](tools/)

## 三个跨层连接器

上述五层不是孤立的。有三篇文档各自跨越两层以上，构成了层与层之间的接口定义：

| 连接器 | 连接 | 核心论点 |
|--------|------|---------|
| [IWE](synthesis/iwe/) | 知识层 ↔ 运行时层 ↔ 演化层 | 把知识资产注入 Agent 沙盒，Agent 在 IWE 中运行时自动产生训练数据 |
| [Agent 工程桥](synthesis/agent-engineering/) | 知识层 ↔ 运行时层 | OpStack 的四个关键决策（框架与事实分离、执行与判断分离等）如何映射到 Agent 架构的控制切面 |
| [Jargon RL](synthesis/jargon-rl/) | 部署层 ↔ 演化层 ↔ 知识层 | IWE 产生的失败日志如何驱动验证器套件生长，CPML 域如何验证这个回路 |

## 一个纵向贯穿的实例：CPML

施工计划建模语言 CPML 及其上层产品 Construction OS 是这个五层栈在施工管理领域的验证：

- **工具层**：Rust 编译器（4000 行）、Python aedile 引擎（5600 行）、React + Three.js 3D 工作台（1200 行）
- **知识层**：场-探针-投影框架定义了施工领域的本体——空间碰撞、资源容量、状态递进、许可在场、材料流速
- **运行时层**：aedile 的 6 个自动化 Agent 负责跨实体数据传导，通过标准化事件解耦
- **部署层**：CPML 编译到 WASM 嵌入浏览器/飞书，项目经理上传计划文件即可获得诊断结果
- **演化层**：CPML 的验证器套件被设计为可从初始场种类和基础断言出发，随模型训练暴露新失败模式而生长

## 从哪里开始

- **如果你在运营团队工作**，每天写周报、审方案、做汇总 → 从 [知识层](knowledge/) 开始，先看 [三层架构与四类资产](knowledge/00-opframework/)
- **如果你在构建 Agent 系统**，关心怎么让 Agent 不出错 → 从 [运行时层](architecture/) 开始，先看 [三层控制回路](architecture/00-three-layer-framework/)
- **如果你在做强化学习/对齐**，关心奖励信号的设计 → 从 [Jargon RL](synthesis/jargon-rl/) 开始
- **如果你做 BIM/施工管理**，关心计划和现实的偏差 → 从 [CPML](domains/cpml/) 开始
- **如果你只是想知道这整套东西的来龙去脉** → 按顺序：知识层 → 运行时层 → 部署层 → 演化层

## 框架的边界

这份框架有几个诚实的声明：

**它不解决文化问题。** 框架假设诚实文化的存在——事实不会被"优化"，策略 owner 不会缺席，日落条款会被执行。工程决定了能力的上限，文化决定了工程的下限能不能被守住。在一个事实被系统性选择性采集的组织中，这套框架不是解药，是冲突加速器。

**它不解决创作和战略。** 框架的目标是让运营不成为瓶颈，同时避免让运营成为天花板。运营只是白领工作的一种模式——环境稳定、标准固定、方法已知、信息完备。创作（高偏差、人类把关）和战略（信息不完备、后果不可逆）不在本框架的管辖范围内。

**它仍在构建中。** 演化层的实验结果空缺，跨层连接器的部分接口仍待形式化，治理层的自指问题（谁来治理治理者）尚未正面回答。
