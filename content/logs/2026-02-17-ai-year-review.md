## 引言

2025 年的 AI 行业围绕一条技术主线展开：**RLVR**（Reinforcement Learning with Verifiable Rewards，可验证奖励强化学习）。

从 DeepSeek-R1 的开源开始，RLVR 在五个层面产生了实际影响：

- **架构层面**：稀疏化 MoE 架构与 RLVR 形成成本-能力正反馈
- **行为层面**：Test Time Scaling 从长 COT 转向短输出+高频工具调用
- **系统层面**：CLI 成为 Agent Runtime 的事实标准
- **协议层面**：MCP 统一了 Agent 与外部工具的交互接口
- **感知层面**：多模态能力让 CLI Agent 能够处理视觉任务

本文梳理这五条线的技术逻辑，以及它们对 2026 年的暗示。

---

## 技术主线

### 1. RLVR 与稀疏化架构的耦合

**技术逻辑**：

```text
RLVR 产生高质量可验证训练数据
         ↓
数据质量足够补偿稀疏架构的信息损失
         ↓
架构可以激进稀疏化 → 推理成本下降
         ↓
RLVR 部署门槛降低 → 循环继续
```

#### 2024 基础：DeepSeek-V3

DeepSeek-V3（2024-12-26）奠定了稀疏 MoE 的基准：671B 总参数 / 37B 激活，训练成本 557.6 万美元，激活率仅 5.5%。

#### 2025 架构演进

2025 年国产开源模型在注意力机制和架构效率上的实际进展：

| 时间 | 模型 | 架构创新 | 关键数据 |
|------|------|----------|----------|
| 2025-01 | MiniMax-01 | **Lightning Attention** 混合架构（7:1 线性:Softmax） | 456B 总参 / 45.9B 激活，支持 400 万 tokens 上下文 |
| 2025-04 | Qwen3 | **快思考+慢思考** 混合推理 | 国内首款融合双模式的混合推理模型 |
| 2025-06 | MiniMax-M1 | **混合架构推理模型**，80K COT × 1M 输入 | 效果比肩海外顶尖模型 |
| 2025-07 | Kimi K2 | **MoE 架构** | 1T 总参 / 32B 激活（3.2% 激活率） |
| 2025-10 | Kimi Linear | **KDA** (Kimi Delta Attention) + MLA 混合（3:1） | 48B 总参 / 3B 激活，KV cache -75% |
| 2025-12 | DeepSeek-V3.2 | **DSA** (DeepSeek Sparse Attention) | 保持 671B/37B 规模，长文本推理成本降低 50% |
| 2026-02 | Qwen3.5 | **397B 总参数 / 17B 激活** MoE | 部署显存占用降低 60%，API 每百万 token 低至 0.8 元 |

**关键观察**：

1. **线性注意力的实用化**：MiniMax-01（2025-01）率先大规模部署 Lightning Attention 混合架构（7:1），证明线性注意力在商用模型级别的可行性。

2. **混合架构成为共识**：从 MiniMax-01 的 7:1 到 Kimi Linear 的 3:1，混合比例向更保守的全局注意力倾斜。M1（2025-06）官方定位为"大规模混合架构推理模型"，固化了这一路线。

3. **纯线性注意力的局限**：MiniMax-M1 坚持混合架构而非走向纯线性，验证了纯线性注意力在复杂逻辑推理（COT）任务上的局限，终结了"纯线性取代 Transformer"的争论。

4. **激活率持续下降**：从 DeepSeek-V3 的 5.5% 到 Kimi K2 的 3.2%，稀疏化程度不断加深，推理成本持续下降。

**2026 展望**：国产开源模型在注意力架构上的探索（KDA、DSA、Lightning Attention）存在相互借鉴的可能。混合比例的设计经验可能在 K-3、Qwen4、DeepSeek-V4 中收敛。

### 2. Test Time Scaling 的行为学转移

#### 封闭世界 vs 开放世界

DeepSeek-R1 后的 COT 长度竞赛只在封闭世界有效（数学、逻辑谜题）。**延长 COT 对开放世界任务的边际收益递减**。

开放世界的特征：

- 信息不完整（需要搜索/采样）
- 动态变化（环境状态随时间改变）
- 行动有后果（错误操作不可逆）

**行为模式转移**：

```text
长 COT（内部独白）       →   短输出 + 高频工具调用
封闭世界自包含验证       →   对环境 Ground Truth 采样
```

#### SWE-Bench 的验证

SWE-Bench 定义了可验证的开放世界任务：

| 元素 | 角色 | 验证方式 |
|------|------|----------|
| Issue | 问题描述 | 自然语言理解 |
| Code | 修改上下文 | 代码状态 |
| Test | 可执行检验 | Linter → Unit Test → CI/CD |

关键点：工具调用提供比 GRPO 更稠密的奖励信号。Test 是 RLVR 在代码领域的具体实现。

**2025 年代码模型 SWE-Bench Verified 成绩演进**：

| 时间 | 模型 | 成绩 | 备注 |
|------|------|------|------|
| 2025-02 | Claude 3.7 Sonnet | 62.3% | 框架调整后 70.3% |
| 2025-05 | Claude 4 Opus | 72.5% | ASL-3 安全标准 |
| 2025-09 | Claude Sonnet 4.5 | 77.2% | 并行计算达 82% |
| 2025-11 | Claude Opus 4.5 | 80.9% | 首个突破 80% 的模型 |
| 2025-10 | MiniMax-M2 | 74% | 专为编码与 Agent 工作流优化 |
| 2026-02 | MiniMax-M2.5 | 80.2% | 对标 Claude Opus 4.6 |

### 3. CLI Agent Runtime 的标准化

#### 时间线

| 时间 | 事件 | 意义 |
|------|------|------|
| 2025-02-24 | Claude Code 研究预览版发布 | 与 Claude 3.7 Sonnet 一同推出 |
| 2025-04-16 | OpenAI Codex CLI 开源 | 开发者工具链完整化 |
| 2025-05 | Claude Code GA + MCP 集成 | 正式版发布，支持外部系统连接 |
| 2025-06 | Cursor 2.0 发布 | 支持 8 个 Agent 并行执行 |
| 2025-10 | OpenAI AgentKit 发布 | Agent 平台化里程碑 |
| 2025-12 | Cursor 2.2 发布 | 调试模式、可视化编辑器 |

RLVR 训练数据以代码为主，模型-环境交互范式自然收敛到 CLI。

#### 两种设计哲学

| 模式 | 代表 | 工具数量 | 交互 | 适用场景 |
|------|------|----------|------|----------|
| 全能型 | Claude Code | 20+ 精细工具，TUI | 同步 | 复杂工程任务 |
| 极简型 | Codex CLI | bash, write, edit, read | 异步 | 快速原型开发 |

#### 控制向量标准化

CLI Agent 的四个配置层逐渐收敛：

- **AGENTS.md**：项目上下文配置
- **Agent Skills**：能力声明
- **Agent Hooks**：生命周期治理
- **Kick-off Prompt**：任务注入

#### 范式变化

复杂 DAG（LangChain/LangGraph）被简单工具链取代。Bash 成为 Agent 的核心运行时。

### 4. MCP：Agent 生态的 USB 端口

**背景**：2024 年 11 月，Anthropic 推出 MCP（Model Context Protocol），2025 年被 OpenAI、Cursor、Google 等全面支持。

**核心功能**：

```text
应用 ←→ MCP 服务器 ←→ 外部工具/API
```

- 即插即用工具集成
- 标准化安全和访问控制
- 模型与工具解耦

**MCP 2025 时间线**：

| 时间 | 进展 |
|------|------|
| 2025-02 | Cursor 预配置 MCP 处理程序 |
| 2025-04 | MCP 图像支持 |
| 2025-05 | Claude Code 集成 MCP |
| 2025-12 | 增强 MCP 与 Figma、GitHub 等集成 |

**MCP 的意义**：解决了 Agent 与外部工具集成的"碎片化"痛点，类比 USB 之于计算机。

### 5. 多模态作为 CLI 的视觉延伸

> CLI Agent 获得了视觉能力，而不是"Agent 需要 GUI"。

**模型进展**：

| 时间 | 模型 | 关键数据 |
|------|------|----------|
| 2025-09 | Qwen3-Omni | 原生端到端多语种全模态 |
| 2026-01-27 | Kimi K2.5 | 1T 参数 / 32B 激活，原生多模态架构，Agent Swarm 机制 |
| 2026-02-16 | Qwen3.5 | 397B 总参数 / 17B 激活，视觉-语言-推理统一 |

**能力扩展**：

视觉输入作为命令参数：

```bash
screenshot | model read
```

RLVR 扩展到视觉验证：

```text
assert result == x           →   assert screenshot matches design_system
```

CLI 控制 GUI 的三种形态：

| 形态 | 接口 |
|------|------|
| 移动端 | 系统级 CLI 指令 |
| PC 端 | Bash 式命令操作 |
| 浏览器 | `navigate`, `click`, `screenshot` |

入口争夺：手机厂商（系统级权限）vs 超级 APP（高频场景）。

## 2026 年的四个预测

### 1. Agent Swarm / Teams

**已有信号**：

| 时间 | 产品 | 特性 |
|------|------|------|
| 2025-03 | OpenAI Agents SDK | Handoffs 机制 |
| 2025-06 | Cursor 2.0 | 8 个 Agent 并行执行 |
| 2025-09 | Claude Sonnet 4.5 | 代理编码能力 |
| 2026-01 | Kimi K2.5 | Agent Swarm（100 个动态分身，1500 步并行） |
| 2026-02 | Claude Opus 4.6 | 自动化代理协调功能 |

**逻辑**：高频采样 → 单 Agent 吞吐受限 → CLI 标准化 → Agent 可共享环境 → 多 Agent 协作成为必然。

**预测**：编排从"单 Agent 工具调用"演进为"多 Agent 任务分解与协作"。

---

### 2. HIOL 取代 HITL

- **HITL**（Human-In-The-Loop）：人在关键节点审批
- **HIOL**（Human-On-The-Loop）：人设定边界后旁观，异常时介入

**逻辑**：稠密奖励 → Agent 行为可预测；短输出+采样 → 每个动作可回滚；控制向量 → 人类意图可精确编码。

**预测**：用户从"审批每个动作"转向"设定边界+异常告警"。

---

### 3. Issue Ticket 成为通信载体

**逻辑**：Swarm/Teams → Agent-Agent 通信需求爆发；HIOL → Human-Agent 通信需更高带宽；环境采样 → 上下文同步需求增加。

**瓶颈**：当前通信缺乏标准化载体，上下文丢失严重。

**预测**：Issue Ticket 成为意图-设计-实现-评估的沉淀载体：

| 阶段 | Ticket 承载内容 |
|------|-----------------|
| 意图 | Ticket 描述 |
| 设计 | 评论记录 |
| 实现 | 关联 Code Change |
| 评估 | 关闭条件 = 验证通过 |

Issue Ticket 是 SWE-Bench 三元组的自然延伸。

---

### 4. Oracle 扩展到更多领域

**定义**：Oracle = 可验证奖励提供机制。

**逻辑**：RLVR 依赖稠密奖励；CLI 普及 → 任何领域可被命令化；多模态 → 视觉验证扩展到非代码领域。

**预测**：Oracle 从软件工程扩展到：

| 领域 | 验证机制 |
|------|----------|
| 数据工程 | schema、分布、异常断言 |
| 基础设施 | Terraform Plan、K8s 状态验证 |
| 产品设计 | UI 截图与 Design System 对比 |
| 内容审核 | 多模态合规验证 |

每个领域的 Oracle 成熟，都将触发该领域的 RLVR 应用。

## 总结

2025 年的核心变化：**RLVR 让 AI 从模仿转向探索**。

五个层面的连锁反应：

- **架构**：稀疏化可行，推理成本下降；国产模型在注意力机制上形成 KDA/DSA/Lightning Attention 等多条探索路径
- **行为**：短输出+高频采样取代长 COT
- **系统**：CLI 成为 Agent Runtime 标准
- **协议**：MCP 统一 Agent 与外部工具的交互
- **感知**：多模态是 CLI 的视觉延伸

共同指向：**可验证性是 AI 工程的核心约束**。

2026 年的问题：**哪些领域能建立自己的 Oracle？**
